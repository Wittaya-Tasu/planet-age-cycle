# หลักการแปลงวันเดือนปีและเวลาเกิดเป็นข้อมูลปฏิทินโหราศาสตร์ไทย

**ชื่อเอกสาร:** Thai Astrology Calendar Conversion Principles  
**รุ่น:** 1.0  
**วันที่จัดทำ:** 16 สิงหาคม พ.ศ. 2569  
**สถานะ:** ข้อกำหนดหลักสำหรับนำไปพัฒนาระบบ  

---

## 1. วัตถุประสงค์

เอกสารนี้กำหนดหลักการสำหรับระบบที่รับข้อมูลวันเดือนปีเกิดและเวลาเกิด (ถ้าทราบ) แล้วแปลงเป็นข้อมูลต่อไปนี้

1. วันในสัปดาห์: อาทิตย์ จันทร์ อังคาร พุธ พฤหัสบดี ศุกร์ หรือเสาร์
2. เดือนโหราศาสตร์หรือเดือนจันทรคติไทย: เดือนอ้าย เดือนยี่ เดือนสาม ฯลฯ
3. เดือนไทยแบบสุริยคติ: มกราคม กุมภาพันธ์ มีนาคม ฯลฯ
4. ปีนักษัตร: ชวด ฉลู ขาล ฯลฯ
5. ปีจุลศักราช (จ.ศ.)
6. ปีคริสต์ศักราช (ค.ศ.)

ระบบต้องคำนวณข้อมูลได้ด้วยตัวเอง ไม่ต้องเรียกเว็บไซต์อ้างอิงทุกครั้ง และต้องเก็บชื่อวิธีคำนวณกับรุ่นข้อมูลไว้เพื่อให้ตรวจสอบย้อนหลังได้

> **คำจำกัดความในเอกสารนี้:** “เดือนไทย” หมายถึงชื่อเดือนสุริยคติภาษาไทย เช่น มกราคม–ธันวาคม ส่วน “เดือนโหราศาสตร์” หมายถึงเดือนจันทรคติไทย เช่น เดือนอ้าย–เดือนสิบสอง

## 2. ขอบเขตของระบบ

### 2.1 ข้อมูลนำเข้า

| ฟิลด์ | จำเป็น | รูปแบบที่แนะนำ | หมายเหตุ |
|---|---:|---|---|
| วันที่เกิด | จำเป็น | 1–31 | ต้องตรวจสอบให้สัมพันธ์กับเดือนและปี |
| เดือนเกิด | จำเป็น | 1–12 | หมายถึงเดือนสุริยคติ |
| ปีเกิด | จำเป็น | พ.ศ. หรือ ค.ศ. | ต้องระบุชนิดศักราชให้ชัด |

| เขตเวลา | ค่าเริ่มต้น | Asia/Bangkok (UTC+07:00) | ห้ามใช้ UTC โดยไม่แปลงกลับเป็นเวลาไทย |

## 3. หลักพื้นฐานที่ห้ามปะปนกัน

ระบบต้องแยกเส้นวันและปีออกเป็นอย่างน้อย 3 ระบบ เพราะไม่ได้เปลี่ยนพร้อมกัน

| ระบบ | จุดเปลี่ยน | ใช้คำนวณ |
|---|---|---|
| วันสุริยคติสากล | 00:00 น. | วันในสัปดาห์ เดือนมกราคม–ธันวาคม และปี ค.ศ. |
| วันจันทรคติไทย | เวลาอาทิตย์ขึ้นจริง หรือประมาณ 06:00 น. | ขึ้น–แรม ค่ำ และเดือนอ้าย–เดือนสิบสอง |
| ปีจุลศักราช | วันและเวลาเถลิงศกของปีนั้น | ปี จ.ศ. และกาลโยค |

ข้อผิดพลาดที่พบบ่อยคือใช้เวลา 00:00 น. เป็นจุดเปลี่ยนของทุกระบบ ซึ่งทำให้ผลผิดสำหรับผู้เกิดช่วงหลังเที่ยงคืนแต่ก่อนอาทิตย์ขึ้น และผู้เกิดในวันเถลิงศกก่อนเวลาที่ศักราชเปลี่ยน

## 4. หลักการคำนวณทีละรายการ

## 4.1 การแปลง พ.ศ. เป็น ค.ศ.

สำหรับวันที่สมัยใหม่และการเก็บข้อมูลแบบปฏิทินเกรกอเรียน ให้ใช้

```text
ค.ศ. = พ.ศ. - 543
พ.ศ. = ค.ศ. + 543
```

ตัวอย่าง

```text
พ.ศ. 2527 - 543 = ค.ศ. 1984
```

### ข้อควรระวังสำหรับข้อมูลประวัติศาสตร์

ประเทศไทยเคยเปลี่ยนปี พ.ศ. ในวันที่ 1 เมษายน และก่อนหน้านั้นเคยใช้วันขึ้น 1 ค่ำ เดือน 5 เป็นจุดเปลี่ยนปี การนำสูตร `พ.ศ. - 543` ไปใช้ย้อนหลังโดยไม่แยก “ปีตามปฏิทินสากล” ออกจาก “ปี พ.ศ. ที่ใช้จริงในสมัยนั้น” อาจทำให้ข้อมูลระหว่างเดือนมกราคม–มีนาคมคลาดหนึ่งปี

ดังนั้นระบบควรมีโหมดดังนี้

| โหมด | วิธีใช้ |
|---|---|
| `modern_proleptic` | ใช้ พ.ศ. = ค.ศ. + 543 ตลอดช่วงข้อมูล เหมาะกับระบบทั่วไป |
| `historical_thai` | แสดงปี พ.ศ. ตามกติกาที่ใช้จริงในแต่ละยุค เหมาะกับข้อมูลประวัติศาสตร์ |

รุ่นแรกของระบบควรใช้ `modern_proleptic` และแสดงคำเตือนเมื่อวันที่อยู่ก่อน 1 มกราคม พ.ศ. 2484

## 4.2 การหาวันในสัปดาห์

### กติกาหลัก

1. แปลงปีเป็น ค.ศ.
2. ตรวจสอบว่าวันที่เป็นวันที่จริงในปฏิทินเกรกอเรียน
3. คำนวณเลขวันจูเลียน (Julian Day Number: JDN) หรือใช้ไลบรารีปฏิทินเกรกอเรียนที่ผ่านการทดสอบ
4. แปลงเศษจากการหารด้วย 7 เป็นชื่อวัน

สูตร JDN สำหรับวันที่เกรกอเรียนที่เป็นจำนวนเต็ม

```text
a = floor((14 - month) / 12)
y = yearCE + 4800 - a
m = month + 12a - 3

JDN = day
    + floor((153m + 2) / 5)
    + 365y
    + floor(y / 4)
    - floor(y / 100)
    + floor(y / 400)
    - 32045
```

กำหนดการแปลค่า `JDN mod 7`

| ค่า | วัน |
|---:|---|
| 0 | จันทร์ |
| 1 | อังคาร |
| 2 | พุธ |
| 3 | พฤหัสบดี |
| 4 | ศุกร์ |
| 5 | เสาร์ |
| 6 | อาทิตย์ |

### บทบาทของเวลาเกิด

วันหลักที่ระบบแสดงในฟิลด์ `civil_weekday` ต้องยึดวันที่ในสูติบัตรและเปลี่ยนวันเวลา 00:00 น. เสมอ เวลาเกิดไม่ทำให้วันสุริยคติย้อนกลับไปเป็นวันก่อนหน้า

หากในอนาคตต้องการ “วันทางโหราศาสตร์ที่นับวันใหม่เมื่ออาทิตย์ขึ้น” ให้สร้างฟิลด์ใหม่ชื่อ `astrological_weekday` แยกจาก `civil_weekday` ห้ามเขียนทับกัน

## 4.4 การหาเดือนโหราศาสตร์หรือเดือนจันทรคติไทย

เดือนจันทรคติไทยไม่ตรงกับเดือนมกราคม–ธันวาคม และไม่สามารถใช้ตารางจับคู่เดือนแบบคงที่ได้ ต้องคำนวณหรือค้นจากเครื่องยนต์ปฏิทินสุริยจันทรคติไทย

### ชื่อเดือน

| รหัส | ชื่อที่แสดง | หมายเหตุ |
|---:|---|---|
| 1 | เดือนอ้าย | เดือนหนึ่ง |
| 2 | เดือนยี่ | เดือนสอง |
| 3 | เดือนสาม |  |
| 4 | เดือนสี่ |  |
| 5 | เดือนห้า |  |
| 6 | เดือนหก |  |
| 7 | เดือนเจ็ด |  |
| 8 | เดือนแปด | เดือนแปดหนแรกในปีอธิกมาส |
| 88 | เดือนแปดหลัง | มีเฉพาะปีอธิกมาส |
| 9 | เดือนเก้า |  |
| 10 | เดือนสิบ |  |
| 11 | เดือนสิบเอ็ด |  |
| 12 | เดือนสิบสอง |  |

### จำนวนวันของเดือน

1. ข้างขึ้นมี 15 วันทุกเดือน
2. เดือนคู่ 2, 4, 6, 8, 10 และ 12 มีข้างแรม 15 วัน
3. เดือนคี่ 1, 3, 5, 7, 9 และ 11 มีข้างแรม 14 วัน
4. ปีอธิกวารเพิ่มแรม 15 ค่ำในเดือน 7 ทำให้ปีมี 355 วัน
5. ปีอธิกมาสเพิ่มเดือน 8 หลังอีก 30 วัน ทำให้ปีมี 384 วัน
6. ปีปกติมาสปกติวารมี 354 วัน

### จุดเปลี่ยนวันจันทรคติ

รอบวันทางจันทรคติไทยเริ่มเมื่อดวงอาทิตย์ขึ้นจริง หรือใช้เวลาประมาณ 06:00 น. หากไม่มีข้อมูลสถานที่และเวลาอาทิตย์ขึ้น

หลักการประมวลผล

```text
ถ้าไม่ทราบเวลาเกิด:
    ใช้รายการจันทรคติของวันที่สุริยคติที่กรอก
    ถ้าวันนั้นมีรอยต่อภายในวัน ให้แจ้งว่าเวลาไม่ทราบ

ถ้าทราบเวลาเกิดและใช้โหมดประมาณ 06:00 น.:
    เวลา 00:00–05:59 ให้ใช้วันจันทรคติของวันสุริยคติก่อนหน้า
    เวลา 06:00–23:59 ให้ใช้วันจันทรคติของวันสุริยคติเดียวกัน

ถ้ามีสถานที่เกิดและใช้โหมดเวลาอาทิตย์ขึ้นจริง:
    คำนวณเวลาอาทิตย์ขึ้น ณ สถานที่เกิด
    เปรียบเทียบเวลาเกิดกับเวลาอาทิตย์ขึ้น
```

### วิธีจัดทำเครื่องยนต์ข้อมูล

ไม่ควรหาขึ้น–แรมด้วยสูตรลัดจากข้างขึ้นข้างแรมทางดาราศาสตร์เพียงอย่างเดียว เพราะปฏิทินจันทรคติไทยมีหลักการวางอธิกมาสและอธิกวารของตนเอง

แนวทางที่แนะนำสำหรับระบบช่วงประมาณ 100–400 ปีคือ

1. สร้างชุดข้อมูลวันเริ่มต้นของทุกเดือนจันทรคติจากหลักปฏิทินสุริยจันทรคติไทย
2. ระบุชนิดปีว่าเป็นปกติมาส อธิกมาส หรืออธิกวาร
3. สร้างวันถัดไปตามจำนวนวันที่กำหนด
4. ตรวจผลกับแหล่งอิสระมากกว่าหนึ่งแห่ง
5. เก็บข้อมูลไว้ภายในระบบเพื่อให้ทำงานแบบออฟไลน์ได้
6. บันทึก `dataset_version` และ `validation_status` ทุกครั้งที่ปรับข้อมูล

ข้อมูลขั้นต่ำต่อหนึ่งวันควรมี

```text
solar_date
lunar_phase          # waxing / waning
lunar_day            # 1–15
lunar_month_code     # 1–12 หรือ 88
lunar_year_type      # normal / adhikavara / adhikamasa
source_version
validation_status
```

## 4.5 การหาปีนักษัตร

### มาตรฐานหลักของเอกสารนี้

ใช้เกณฑ์โหราศาสตร์ไทยตามคติพราหมณ์–ฮินดู โดยเปลี่ยนปีนักษัตรใน **วันขึ้น 1 ค่ำ เดือน 5** ณ เวลาเริ่มวันจันทรคติ

ลำดับนักษัตรวนรอบทุก 12 ปี ดังนี้

| ดัชนี | ปีนักษัตร |
|---:|---|
| 0 | ชวด |
| 1 | ฉลู |
| 2 | ขาล |
| 3 | เถาะ |
| 4 | มะโรง |
| 5 | มะเส็ง |
| 6 | มะเมีย |
| 7 | มะแม |
| 8 | วอก |
| 9 | ระกา |
| 10 | จอ |
| 11 | กุน |

### สูตรโดยใช้ปี ค.ศ. 1984 เป็นปีฐาน

หลังผ่านวันขึ้น 1 ค่ำ เดือน 5 ของ ค.ศ. 1984 แล้วเป็นปีชวด จึงใช้ปีฐานดังนี้

```text
ถ้า timestamp เกิด >= จุดเริ่มขึ้น 1 ค่ำ เดือน 5 ของปี ค.ศ. Y:
    cycleYear = Y
มิฉะนั้น:
    cycleYear = Y - 1

zodiacIndex = mod(cycleYear - 1984, 12)
zodiacYear  = zodiacNames[zodiacIndex]
```

ฟังก์ชัน `mod` ต้องให้ผล 0–11 แม้ค่าตั้งต้นเป็นจำนวนลบ

### กรณีไม่ทราบเวลาเกิด

ถ้าวันเกิดไม่ใช่วันขึ้น 1 ค่ำ เดือน 5 สามารถแสดงปีนักษัตรได้ตามปกติ แต่ถ้าเกิดตรงวันเปลี่ยนปีนักษัตรและไม่ทราบเวลา ระบบต้องแสดงสองความเป็นไปได้ เช่น

```text
ปีนักษัตร: กุน หรือ ชวด
หมายเหตุ: เกิดตรงวันเปลี่ยนปีนักษัตร แต่ไม่ทราบเวลาเกิด
```

### เกณฑ์อื่นที่อาจเพิ่มภายหลัง

| รหัส | จุดเปลี่ยนปีนักษัตร | การใช้งาน |
|---|---|---|
| `thai_astrology_month5` | ขึ้น 1 ค่ำ เดือน 5 | ค่าเริ่มต้นสำหรับโหราศาสตร์ไทย |
| `royal_calendar_month1` | ขึ้น 1 ค่ำ เดือนอ้าย | ปฏิทินหลวง/งานทะเบียนบางประเภท |
| `thaloeng_sok` | วันและเวลาเถลิงศก | บางสำนักโหราศาสตร์ |
| `fixed_january_1` | 1 มกราคม | บางตำราสมัยใหม่ |
| `fixed_april_1` | 1 เมษายน | บางตำรา |

ระบบต้องเก็บรหัสเกณฑ์ที่ใช้ ห้ามแสดงเพียงชื่อปีนักษัตรโดยไม่ทราบวิธีคำนวณ

## 4.6 การหาปีจุลศักราช

ปีจุลศักราชไม่ได้เปลี่ยนวันที่ 1 มกราคม แต่เปลี่ยนใน **วันและเวลาเถลิงศก** ซึ่งคำนวณตามคัมภีร์สุริยยาตร์ และมักอยู่ช่วงกลางเดือนเมษายน

### หลักการคำนวณ

สำหรับปี ค.ศ. `Y`

```text
candidateCS = Y - 638
boundary    = วันและเวลาเถลิงศกของ candidateCS ตามสุริยยาตร์

ถ้า timestamp เกิด >= boundary:
    จ.ศ. = candidateCS
มิฉะนั้น:
    จ.ศ. = candidateCS - 1
```

ตัวอย่างสำหรับ ค.ศ. 1984

```text
candidateCS = 1984 - 638 = 1346
วันเถลิงศก = 15 เมษายน 1984 เวลา 17:51 น. ตามชุดข้อมูลอ้างอิง

ก่อน 15 เมษายน 1984 เวลา 17:51 น.  -> จ.ศ. 1345
ตั้งแต่ 15 เมษายน 1984 เวลา 17:51 น. -> จ.ศ. 1346
```

### วิธีหาเวลาเถลิงศก

รุ่นใช้งานจริงต้องเลือกหนึ่งในสองแนวทาง

| แนวทาง | รายละเอียด | ข้อเสนอแนะ |
|---|---|---|
| เครื่องยนต์สุริยยาตร์ | คำนวณวันเวลาเถลิงศกตามสูตรและค่าคงที่ของคัมภีร์ | เหมาะกับระบบระยะยาว แต่ต้องทดสอบเข้มงวด |
| ตารางขอบเขตเถลิงศกรายปี | เก็บวันเวลาเถลิงศกของทุกปีในช่วงที่รองรับ | เหมาะกับระบบปฏิทิน 100 ปี ตรวจสอบง่ายและเสี่ยงน้อยกว่า |

สำหรับรุ่นแรก แนะนำให้ใช้ **ตารางขอบเขตเถลิงศกรายปีที่ผ่านการตรวจสอบ** และพัฒนาเครื่องยนต์สุริยยาตร์เป็นรุ่นถัดไป ระบบจึงไม่ต้องเรียกเว็บไซต์ภายนอกขณะใช้งาน

### กรณีไม่ทราบเวลาเกิด

หากเกิดตรงวันเถลิงศกแต่ไม่ทราบเวลา ระบบต้องแสดง จ.ศ. ได้สองค่าและแจ้งความกำกวม ห้ามสมมติว่าเปลี่ยนศักราชเวลา 00:00 น.

## 5. ลำดับการประมวลผลรวม

```text
INPUT: วัน, เดือน, ปี, ชนิดศักราช, เวลาเกิด (ถ้ามี)

1. ตรวจสอบความถูกต้องของข้อมูล
2. แปลงปีเป็น ค.ศ. แบบ modern_proleptic
3. สร้าง civilTimestamp ในเขตเวลา Asia/Bangkok
4. คำนวณ civil_weekday จากวันที่เกรกอเรียน
5. แปลงเลขเดือนเป็น thai_solar_month_name
6. กำหนด lunarEffectiveDate
   - ไม่ทราบเวลา: ใช้วันที่สุริยคติและตรวจธงวันรอยต่อ
   - ทราบเวลาและก่อนจุดเริ่มวันจันทรคติ: ใช้ข้อมูลจันทรคติวันก่อนหน้า
7. ค้น lunar_month_code และ lunar_month_name จากเครื่องยนต์จันทรคติ
8. หาเวลาขึ้น 1 ค่ำ เดือน 5 ของปีนั้น
9. คำนวณ zodiac_year ตามเกณฑ์ thai_astrology_month5
10. หาเวลาเถลิงศกของปีนั้น
11. คำนวณ chulasakarat
12. เพิ่ม calculation_method, dataset_version และ warnings
13. ส่งผลลัพธ์
```

## 6. กติกาเมื่อไม่ทราบเวลาเกิด

| รายการ | คำนวณได้หรือไม่ | วิธีจัดการ |
|---|---:|---|
| วันในสัปดาห์ | ได้ | ใช้วันที่สุริยคติ |
| เดือนไทยสุริยคติ | ได้ | ใช้เลขเดือน |
| ปี ค.ศ. | ได้ | ใช้สูตรแปลงศักราช |
| เดือนจันทรคติ | ได้เกือบทุกวัน | ถ้าเป็นวันรอยต่อให้แจ้งความกำกวม |
| ปีนักษัตร | ได้เกือบทุกวัน | ถ้าเป็นวันขึ้น 1 ค่ำ เดือน 5 ให้แสดงสองค่า |
| ปีจุลศักราช | ได้เกือบทุกวัน | ถ้าเป็นวันเถลิงศกให้แสดงสองค่า |

หลักสำคัญคือ **เวลาไม่ทราบต้องเป็น `null`** ห้ามแทนด้วย 00:00 น. เพราะการแทนเวลาเองอาจทำให้เดือนจันทรคติ ปีนักษัตร หรือ จ.ศ. ผิด

## 7. ตัวอย่างผลลัพธ์

### ตัวอย่าง: 21 เมษายน พ.ศ. 2527 เวลา 01:49 น.

| รายการ | ผลลัพธ์ |
|---|---|
| วันสุริยคติ | วันเสาร์ |
| เดือนโหราศาสตร์ | เดือนห้า (5) |
| เดือนไทยสุริยคติ | เมษายน |
| ปีนักษัตร | ชวด |
| ปีจุลศักราช | 1346 |
| ปี ค.ศ. | 1984 |

ข้อมูลสอบทานของวันที่ 21 เมษายน พ.ศ. 2527 ระบุว่าเป็นวันเสาร์ แรม 6 ค่ำ เดือน 5 ปีชวด และอยู่หลังวันเถลิงศกของปีนั้นแล้ว จึงเป็น จ.ศ. 1346

เวลา 01:49 น. อยู่ก่อน 06:00 น. หากเปิดโหมดวันจันทรคติเริ่มเมื่ออาทิตย์ขึ้น `lunarEffectiveDate` จะย้อนกลับไปใช้ข้อมูลจันทรคติของวันที่ 20 เมษายน อย่างไรก็ตาม วันที่ 20 และ 21 เมษายนยังอยู่ในเดือน 5 ปีชวดและ จ.ศ. 1346 เหมือนกัน ผลลัพธ์หกรายการที่เอกสารนี้กำหนดจึงไม่เปลี่ยน

ตัวอย่างโครงสร้างข้อมูล

```json
{
  "input": {
    "date_be": "2527-04-21",
    "time": "01:49",
    "timezone": "Asia/Bangkok"
  },
  "result": {
    "civil_weekday": "เสาร์",
    "lunar_month_number": 5,
    "lunar_month_name": "เดือนห้า",
    "thai_solar_month_name": "เมษายน",
    "zodiac_year": "ชวด",
    "zodiac_method": "thai_astrology_month5",
    "chulasakarat": 1346,
    "christian_era": 1984
  },
  "metadata": {
    "calculation_method": "Thai-lunisolar/Suriyayatra-v1",
    "time_known": true,
    "warnings": []
  }
}
```

### เกณฑ์ผ่านขั้นต่ำ

4. ผลที่ไม่แน่นอนเพราะไม่ทราบเวลาต้องแสดงความกำกวม ไม่เลือกคำตอบเอง
5. ทุกผลลัพธ์ต้องระบุรุ่นวิธีคำนวณและรุ่นฐานข้อมูล

## 12. ข้อสรุปสำหรับผู้พัฒนา

ระบบนี้ไม่ใช่การนำปี พ.ศ. ไปลบ 543 แล้วจับคู่เดือนแบบตายตัวเท่านั้น แต่ต้องใช้เครื่องยนต์ปฏิทินสามส่วนร่วมกัน

1. **เครื่องยนต์เกรกอเรียน** — วันในสัปดาห์ เดือนสุริยคติ และ ค.ศ.
2. **เครื่องยนต์จันทรคติไทย** — เดือนอ้าย–เดือนสิบสอง อธิกมาส และอธิกวาร
3. **เครื่องยนต์รอยต่อโหราศาสตร์** — ปีนักษัตรและจุลศักราชตามเวลาเปลี่ยนจริง

หากระบบแยกทั้งสามส่วนชัดเจน เก็บเวลาที่ไม่ทราบเป็น `null` และมีชุดทดสอบวันรอยต่อ ระบบจะสามารถทำงานได้โดยไม่ต้องพึ่ง MyHora ขณะใช้งาน พร้อมตรวจสอบย้อนกลับได้ว่าแต่ละผลลัพธ์เกิดจากกฎและข้อมูลรุ่นใด
